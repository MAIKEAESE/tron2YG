## 交替门控：两版实现的区别（审查报告 #2 的教训）

| | 首帧版（废弃） | 锁存版（当前） |
|---|---|---|
| 判定时机 | 每帧比较摆动脚 | **新摆动事件开始时**判定一次 |
| 系数 | 换腿后仅首帧 1.0，其余 0.3 | **整次摆动锁存**：换腿 1.0 / 同腿 0.3 |
| 交替 vs 扑腾收入比 | 1.16×（钝刀） | **≈3.3×**（设计意图） |
| 去抖 | 无（微抬即误判） | 两帧持续才确认新事件 |

## 审查报告确认的系统性问题（未修，下一轮优先级）

1. **P1 出生 z 不随地形**：台阶段出生在实体内部 → 物理弹射 → 需地形感知出生
2. **P1 base_height 世界 z**：爬升后奖励死 → 需相对支撑面
3. **P1 评估终态污染**：step 内自动 reset → done 环境读的是下一回合出生 → 需 reset 前缓存
4. **P1 提交适配断层**：actor 235 维 vs 提交 48 维，模态不同 → 需蒸馏或重新对齐
5. 地形百格只用第 0 行 10 格（curriculum=False）→ 下一轮
6. PLAY 20s/35° vs 训练 30s/50° → 评估失败率被放大
