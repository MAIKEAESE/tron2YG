## 0. 项目定位

**起点诊断**：7 月旧线的失败根源是"站立优先"课程结构——站立先验烙进网络，后续所有阶段都在与之搏斗，奖励栈膨胀到 ~40 项互相打架（内八、偏移、台阶不抬腿）。

**战略**：废弃旧链，从零直接训 Perceptive Gait（站立降级为 0 速命令模式），奖励写"结果"不写"形态"，配套建测量体系（审计/评估/录像），迭代由数据裁决。

## 2. v6 设计（依据链）

**证据**：
1. v5 遥测：平地出生 27% 行走 vs 坡段/中段出生 **0%**（速死 <2s）——时间表课程从第 300ep 起强制 20% 中段出生 = 烧 GPU 买零信号
2. NVIDIA（legged_gym/Isaac Lab）范式对比：难度解锁按**实测走出距离**（每 env 每 episode 升降级），我们的同款机制（promote 4m / demote 1.2m / 5 级）**早已写好但从未接线**（`adaptive_level_weights=None`）
3. 奖励账核算：shortfall（命令门控，站立局恒 0）在行走局只罚 ~0.4/步，盖不住站立收入 +1.5/步

**改动（+18/−2，全部在 scratch 函数内）**：
- `forward_speed_shortfall`：−1.5→**−2.5**，死区 0.05→**0.03** → 行走命令下站立净收入 **+1.1 → −0.1/步**（信号门控机制本体已内建于 shortfall，加重即实现"有方向信号才罚"）
- `adaptive_level_weights` 接线：L0=纯平地 → L1=+坡40% → L2=+下坡 → L3=+台阶30% → L4=台阶40%；晋升=走出≥4m，降级=<1.2m，掌握等级随机复习；bumps 五档全 0
- `phase_schedule` 压平为均匀基底（必须：采样=phase×level 逐元素乘，时间表不平则等级永远无效）

**未做（v7 弹药）**：方向随等级多样化（用户提案的"或者"分支，需课程↔命令运行时耦合 ~50 行）；位置结果奖励（w×Δx）；keep_balance 0.6→0.4。

**验收线（预登记）**：平地>2m 行走率 ≥50% ｜ P75 ≥2m ｜ L2+ 环境行走率非零 ｜ 形态四项不回退 ｜ 校正后 progress ≥4m。

## 3. 方法论资产（可复用）

| 工具 | 功能 | 关键教训 |
|---|---|---|
| `reward_audit.py` | 随机策略奖励尺度审计（分位数/激活率/episode贡献/摔前峰值+四标记） | foot_contact_force 是"偶发冲击"型非"承重主导"型；门控项死活=预期内 |
| `eval_protocol.py` | 固定 seed 评估：进度/分段通过/姿态遥测（duty/交换率/步宽/横滚）+ 场景签名配对 | **签名验证发现 50% 顺序配对是错的**；progress 有出生赠品 ~1.9m 偏差 |
| `play.py` 增强版 | URL 下载 checkpoint、有界播放、跟随相机录像 | OOM 教训：300 帧+performance 渲染 |
| 分析流程 | McNemar 精确检验、配对 bootstrap、held-out 复核 | 单块 3σ≠趋势；N_eff 公式有前提；"证据不足"≠"无变化" |

**流程纪律**（全部由翻车换来的）：训练曲线只作线索、能力结论只出自固定评估；每刀预登记假设与验收线；失败样本不剔除（降级重定向）；统计宣称附条件与窗口。
